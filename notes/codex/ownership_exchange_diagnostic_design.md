This is preparation for a mechanism comparison, not an executable protocol or
authorization to run the corpus. The isolated implementation and independent
review remain in progress. Numerical work/time allowances must be fixed before
the first diagnostic outcome is read.

The initial proposal was to take all 34 independently validated 041 controls
and apply deletion closure. The accepted 042 result now supplies an equivalent
audited starting set without another closure run: all 34 treatment outputs have
complete original-graph trace and single-deletion-minimality certificates, and
their cleanup entries match the unchanged control states. Use every one of these
34 saved outputs, with the original Z12 target and source-label maps. These are
our own algorithm's development outputs, not competitor embeddings or future
pipeline inputs. The purpose is to exclude already safe single-site removals
from ownership-exchange discoveries. The final protocol must bind this whole
set and its existing transformation evidence; no favorable subset is selected.

The useful question is whether the new proposal can expose a contraction at
reasonable cost beyond the existing ordinary group reconstruction. A comparison
must retain all attempted groups, complete failures, work-limit/deadline stops
and unsatisfied opportunity counts. No returned candidate is not proof that a
contraction is absent. An exact complete ownership partition oracle is useful
only on tiny fixtures; a global exact solve is outside this approach.

Compare proposals from the same immutable starting incumbent and a declared
group sequence. Do not silently give the ordinary control a new global setup
for every group: public `repair_group` currently constructs `_Context` and
validates the full incumbent on each call. A diagnostic adapter would need to
share that immutable context and entry validation while calling the unchanged
ordinary proposer, charging all setup and retaining its fixed reconstruction
options. Such an adapter must be reviewed before use. It would be a proposal
reach comparison, not a replay of the full evolving contact-polish schedule.

The ordinary routing-expansion counter and the new elementary-record counter
measure different operations. Equal numerical limits would not establish equal
work. Record complete wall/CPU costs, setup, generation, validation and all
unsuccessful effort. Choose finite caps and a common wall allowance after tiny
implementation-cost checks, before any corpus probe. A first-contraction result
must be distinguished from the total reduction attainable by repeated accepted
moves. No independent outputs are combined into an algorithm result.

Initial group selection also needs an explicit decision. The existing round-robin
generator orders groups using chain excess, logical neighbors and physical
adjacency; it omits groups whose total individual degree-bound excess is zero.
That omission is not a proof that an ownership exchange with subsequently admitted
donors cannot help. Conversely, a singleton initial group permits only its owner
as the receiver until a donor is admitted, so pairs can expose moves that a
singleton search excludes. The reviewed two-swap toy requires a stated initial
group. Freeze a general selection rule and report its coverage rather than
choosing groups after seeing favorable contractions.

Any promising result still requires a separate full-pipeline experiment with
all costs inside the common deadline. Strict local Q reduction can displace
better later work. Existing free-space reconstruction should remain available
for consideration within one algorithm; occupied-site exchange cannot replace
its reach by assumption. Elementary transfer/swap controls and fresh-instance
validation are needed before a contribution or generalization claim.
