## Counterexample on the exact ideal Z12 graph

Root constructed two explicit valid embeddings of the four-vertex star with
center `u` and leaves `v,w,z`, using the frozen original Z12 target edges.
Leaf chains are fixed at `v:[97]`, `w:[121]`, `z:[2508,204]`.

| Quantity | Embedding A | Embedding B |
| --- | --- | --- |
| Center chain | `[2604,2605,2606]` | `[96,2544,120]` |
| Total Q | 7 | 7 |
| Directed support-one obligations | 6 | 5 |
| Directed support-two obligations | 0 | 1 |
| Immediately deletable qubits, all chains | 2 | 1 |
| Minimum center size by deletion with leaves fixed | 1 | 3 |
| Minimum Q by deleting supplied sites only | 4 | 6 |

The proposed histogram prefers B, even though deletion flexibility worsens.
In B, center endpoints 96 and 120 separately carry the only contacts to leaves
97 and 121, while 2544 is an articulation. The remaining deletable site is on
leaf chain z. A can delete its center tail and remove z's unneeded site.

The stdlib-only [witness script](../../results/codex/endpoint-support-review/zephyr_counterexample.py)
retains physical coordinates, exact IDs, both full embeddings, directed support
sets, all valid single deletions and the tiny nonempty-subset enumeration.
The [saved result](../../results/codex/endpoint-support-review/zephyr_counterexample.corrected.json)
binds the target hash. It uses only 21 candidate subset combinations per supplied
embedding; no embedding constructor, MM, busclique, IP solver or corpus source
instance is invoked. The final source-only correction clarifies that subset
count in a comment; it changes no computation. Independent review then caught
an underspecified result-field name. The corrected record explicitly names
the center minimum as deletion-only; original code/results are retained.
Both unrestricted fixed-leaf center minima are one: site 2604 is a valid
singleton replacement in either state. The corrected tiny check verifies this
certificate and preserves every preceding numerical result.

This is a proxy counterexample, not a failed benchmark. Neither starting state
is deletion-minimal, and neither is claimed to be generated by the existing
bounded proposer. The full target also permits relocations outside these supplied
sites. The current pipeline prunes before refinement, so the witness does not
by itself show that the proposed policy will choose this adverse transition.
It establishes that the score cannot be called an exact final-ACL surrogate,
even on the requested hardware.

## Implementation decision

The current raw-redundancy function scans ownership and target adjacency outside
the search-expansion counter. Equal expansion ceilings do not imply equal total
work. A concrete implementation specification must preserve default behavior,
define any normalized control separately, and expose all added scoring work and
time under the common deadline. It must distinguish acceptance of a known valid
strict-Q improvement from an interrupted equal-Q comparison and preserve signed
raw-contact changes in diagnostics.

Root subsequently read and accepted the complete
[implementation specification](endpoint_support_implementation_spec.md), SHA256
`03cd87e074c8632c1361b7320e2d7942e5482d00505b138909b57d510501b8eb`.
It leaves the legacy R control untouched and adds one experimental objective,
with lazy ownership, exact incident support in both directions, final deadline
checks and nullable signed diagnostics. Lower-Q acceptance needs no secondary
scan. The initial comparison is explicitly a scoring-policy comparison;
implementation timing changes prevent calling it a pure objective ablation.
Bounded implementation and focused tests are authorized, followed by independent
review. No corpus run or scientific success follows from this acceptance.
