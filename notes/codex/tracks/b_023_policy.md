# B023 exact pre-code policy

2026-09-08. Construction with temporary contact loss and overlap. This fixes the selected [hypothesis and critique](b_023_contact_debt_proposal.md) before implementation. B022, all its settings and results remain unchanged. Root approved a new standalone module and one fixed eighteen-call B9 screen, not a sequence of repairs.

**State and initialization.** Inputs are finite simple undirected loopless integer graphs; the initial experiment supports connected target hardware and `|V(G)| <= |V(H)|`. Sort source IDs numerically. Create target rank by `Random(seed).shuffle(sorted(H))`; independently shuffle the numerically sorted source edge list with `Random(seed)`. Source BFS roots/neighbors use decreasing degree then source ID. Target BFS begins at greatest degree then target rank; neighbors use target rank. Pair source BFS with target BFS injectively. Each initial chain is that singleton, including isolates; subsequent moves have no anchor obligation. Preserve this exact initialization record. Chains are connected site sets, not a collection of alternative domains. Ownership sets and oriented physical-coupler counts for each original logical edge determine exact Q, O and M. Two orientations of one hardware edge may be counted when both chains contain both endpoints; M depends only on a positive count.

Maintain unit site prices lambda and unit logical-edge prices mu. At fixed prices, `F = Q + sum(lambda*excess) + sum(mu*missing)`. State updates include all owners on affected physical neighbors, including outside owners. No compulsory coupler witnesses are maintained.

**Interleaving and prices.** At most eight passes over the fixed edge order. Every edge visit, even an already satisfied edge, is followed by one current-conflict visit when any exists. The conflict is the first currently overlapping site at or after a cyclic target-rank cursor; wrap if needed and advance past the selected rank. Thus dense sources do not need to finish thousands of routings before erasure begins. If a visited edge is missing, increment its mu by one before routing. If a site is selected for erasure, increment its lambda by its current excess before erasure. These are committed price observations, timed and counted even if the following private move is interrupted. No other price changes occur. This supersedes the selection note's full-pass price schedule for the stated pre-code cost reason.

```text
initialize once, prices=1; if M=O=0 finish
for at most eight fixed source-edge passes:
    for each edge e in fixed order:
        if e is missing: increase mu[e]; attempt its two directed routes
        if now M=O=0: finish
        if any overlap: select cyclic conflict q; increase lambda[q]; erase one ownership
        if now M=O=0: finish
finish with original-graph validation; return {} unless timely valid
```

An edgeless source is already valid at initialization. An interrupted move ends search; there is no cap reset or alternative restart. Receipts distinguish completed edge visits, routing attempts, erasure visits and price updates, including zero-erasure runs.

**Route and acceptance.** For missing `(u,v)`, run one weighted Dijkstra from each chain to the actual target-neighbor boundary of the other. Own sites have incremental cost zero; every other site costs `1 + lambda[q]` if another logical owner occupies it, otherwise one. All own-chain sites are zero-distance seeds. Neighbors and equal-distance heap ties follow target rank; retain the first predecessor on a strict distance improvement only. Stop at the first settled boundary site, reconstruct a simple predecessor path, and union it with the growing chain. Both directed alternatives use the same entry state/prices. They must be fully scored; choose `(F, O, M, Q, source_ID)` minimum. Commit the chosen route even if F increases, because it removes the selected missing-edge defect. It can create overlap but cannot remove existing contacts. If either search/scoring is interrupted, discard both alternatives and stop; preserve earlier commits and price observations.

**Erasure and acceptance.** For selected overlap site q, inspect owners by source ID. For a chain larger than one, enumerate every connected component of `C_u - {q}` in target rank order; each component is one candidate replacement, discarding all other sites. For a singleton, the replacement is the first globally free site in target rank, if one exists. If none exists, inspect all target neighbors of q as singleton replacements, in target rank. These rules are fixed; no unrestricted singleton root pool. Every candidate is nonempty, connected and excludes q. Score all candidates against the same entry and prices. Choose `(F, O, M, Q, source_ID, sorted_target_rank_signature)` minimum and commit regardless of F descent. A non-singleton cut cannot introduce new overlap; a singleton relocation may move overlap elsewhere. Both can lose actual contacts, which subsequently re-enter the ordinary edge schedule. An interrupted enumeration/scoring publishes no replacement. If no candidate exists, record a completed no-move visit; do not invent feasibility.

**Publication and cost.** Use private replacements and exact affected-edge/site deltas. Prepare the winner's chain/owner/contact changes before an atomic state-pointer publication following the final clock check. Charge normalization, BFS, sorting input records, heap operations, adjacency/site/owner scans, component and boundary construction, scoring, map copying and final output work. Sorting CPU and all other administration remain in the same wall clock. The cumulative meter is 20M units; search stops at 19M and one second before the common 20-second deadline, reserving 1M/one second for final evidence/validation. Other caller timeouts use `min(1 second, 5% of timeout)` reserve. Unlike B022, there is no separate 100k/5-second query limit: a primitive is now one contact route or one component erasure, and all its work consumes the same global allowance. No hidden per-query reset or new root/cap tuning.

On first `M=O=0`, stop the defect search. In the remaining search allowance only, make one deterministic global leaf-pruning pass: source ID then target rank, requeue newly exposed leaves; remove a leaf only if each currently present incident logical contact remains, retaining one site per owner. Each accepted deletion is a completed strict-Q move. This is a single conventional cleanup, not a repeated constructor or another refinement search. An interrupted cleanup retains its valid completed prefix. Original graph validation and output materialization use the final reserve; there is no success credit for zero counters alone or a late return. Save initial/final sets and exact Q/M/O/F, lost/restored-contact counts, signed move deltas, stage work/wall and interrupted candidate evidence; changed prices prevent comparison of endpoint F as a common descent potential.

**Self-critique and gates.** Interleaving can cycle a contact immediately after building it, while increasing prices need not converge. Cutting to a component may destroy many useful contacts. Initial BFS sites can still create long sparse chains; stopping defect search at first feasibility may retain a poor valid geometry. The singleton fallback is incomplete. This changes initialization, intermediate states, neighborhood and acceptance together; final success would justify a controlled follow-up, not identify a sole cause. Use only targeted exact Q/M/O/contact accounting, a fixed small trajectory that loses then repairs a contact, singleton fallback, and interrupted/late publication checks. If that central primitive fails, stop before a panel. Otherwise root freezes the unchanged nine B inputs, candidate plus fresh stock MM, seed0, twenty seconds: eighteen calls. Require >=7/9 timely valid and Q<=MM on >=3 common timely successes, including optimal ACL1 ties. Report every failure, all-attempt time, first feasibility and cleanup Q, repairs with increasing F, and whether erasure/prices were actually exercised. No intermediate metric compensates for missing the complete-constructor gate.
