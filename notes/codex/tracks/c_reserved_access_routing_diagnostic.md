# Proposed routing-only test after reserved-access initialization

**Hypothesis.** The eight saved initializations give every source chain access to one common unused full-target component. Sequential unused-site paths may realize enough original contacts before that shared access is consumed. The cheapest next test measures this consumption directly, without invoking C006 search or changing construction. C006 `_State`/`_search` use the induced occupied domain and owned-region exchanges; running them unchanged on O would exclude D and cannot test this hypothesis.

**Fixed supplied states and domain.** Use the eight assigned maps in the frozen reserved-access results, in order 2030, 5058, 1584, 31536, 6450, 14334, 1041, 30736. Bind their exact original graphs/label maps, saved U and D, and original ideal Z12 target through the accepted manifests. The supplied occupied set is O = U minus D. Routing uses the original **full** target: currently unused sites are `V(Z12) minus current ownership`, including D and sites outside U. This does not select a different U or rerun initialization. Preserve full physical labels and original-source labels in the independent gate. All eight starts are partial-contact assignments, not full minors of their original graphs.

**One evolving incumbent; fixed scheduling.** Start from a private copy and recount P as every currently realized original source edge. Snapshot entry missing edges in canonical normalized endpoint order. Make one pass through that list:

1. Skip an edge if an earlier commit incidentally realized it. Otherwise obtain the current unused components and chain frontiers, reusing them only while ownership is unchanged. If the endpoint component sets do not intersect, record `sealed_endpoint` or `disconnected_access`, with both endpoint frontiers/component IDs, and continue.
2. When they intersect, call the unchanged audited deterministic multi-source `shortest_free_path` primitive. Block all owned sites. Attach its entire shortest path to the lower-ranked source endpoint in a private proposal. No alternate path or endpoint assignment is tried.
3. Independently validate nonempty connected disjoint chains and every edge of P plus the requested original edge against the original target. Recount **all** realized original edges, require P preservation and a strict decrease in missing contacts, then check the clock before atomic commit. Record incidental contacts and protect them in subsequent proposals. Retain failed/late raw proposals without altering the incumbent.

The canonical single pass avoids recomputing routes for all missing edges before each choice. No second pass is needed for reach: deleting unused vertices cannot merge unused components, and an endpoint grows only through a component already accessible to it. Therefore an edge with disjoint accessible component sets cannot acquire a free route through later addition-only moves. This observation does not assert that the canonical order is best.

**Unchanged diagnostic ceilings and evidence.** Reuse the earlier sequential diagnostic ceilings of 30 seconds, 1,024 still-missing visits and 256 commits per input; use no ownership queries. Setup, input validation, component/BFS work, failed visits, private copies, gates and contact/access recounts all count toward that one deadline. No per-input exception or reset is allowed. Record every skipped, failed and unattempted entry edge; hitting a ceiling is `capped`/`TIMEOUT`, not a proof that no further route exists. No deletion cleanup runs in this routing-only test.

For each committed generation, retain the path, newly realized original edges, added Q, remaining D, connected components of unused D, full-target unused components and sealed-chain IDs. Compute the next access summary under the same deadline; if it is interrupted, identify its generation and incomplete fields explicitly. At the end, separately report P-subgraph validity, full-original-minor validity, timely completion, final missing edges and Q. Preserve the last certified incumbent on interruption and distinguish any later diagnostic validation from timely success. No initialization time is combined with this local supplied-state time to claim a constructor runtime.

**Self-critique and cheap falsifier.** Canonical order and assigning every path to one endpoint can consume a shared reserve prematurely; common initial access does not guarantee simultaneous disjoint routing. The 256-commit/1,024-visit ceilings can censor the dense inputs, so unfinished progress alone is weaker evidence than an observed no-route obstruction. Before supplied-state calls, use one tiny completion fixture, one fixture where the first committed path seals a still-missing endpoint, and failed/final-deadline rollback checks; reuse the existing primitive/oracle without broader enumeration. The mechanism is insufficient for this fixed policy if reserve consumption produces inaccessible required contacts. Completion would support only a later separately specified constructor test. No combined witnesses, reserve refill, ownership exchange, changed target selection, extra seed, MM or corpus constructor call is included. Novelty remains unestablished.
