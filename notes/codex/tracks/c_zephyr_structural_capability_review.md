# Zephyr capability worth retaining in the constructor design

**Read-only design review, not a constructor proposal or implementation authorization.** The useful capability is an exact index of physical rail intervals and their contact supports. It can make local physical placement queries cheaper and more honest than treating every target site as an unrelated bit in a full-width domain. It does not by itself choose good global placements or solve the C011 revision/splitting problem.

I inspected the pinned **dwave-networkx 0.8.19** implementation, [zephyr.py](../../../.venv/codex-native/lib/python3.10/site-packages/dwave_networkx/generators/zephyr.py:37), SHA256 `8bcda95437a6a6836a45fc215a82bb8c2b60e60fbac985e1793bf1826d8122a3`. Its coordinate encoder/decoder is at lines278–314; no generator was executed. The target remains the existing ideal Z12, target digest `38cde794…5938`, whose frozen bytes are bound in [C011's input manifest](../../../results/codex/track-c-011-protocol/preparation_manifest.json).

A site has coordinates `(u,w,k,j,z)`, with orientation u, major line w, track k, staggered course j and longitudinal coordinate z. For Z12, u∈{0,1}, w=0…24, k=0…3, j∈{0,1}, z=0…11. Fixing `(u,w,k,j)` gives one **12-site path**, linked by external edges z↔z+1: 400 rails in total. Physical distance along a rail is a run length, and free sites can be indexed as intervals rather than recomputing every target-neighborhood mask.

The actual edge loops matter:

- External edges extend the same course by one z step.
- Odd edges link `(u,w,k,0,z)` to `(u,w,k,1,z)` and, where present, `(u,w,k,1,z−1)`. The paired courses provide local turns and short detours, but an occupied alternate course can block them.
- Cross-orientation couplers use the staggered parity offsets in the internal-edge loop (lines207–211). A drawn crossing is insufficient: the actual endpoint pair must be in target adjacency. Boundary truncation also matters.

One coherent physical state could therefore carry owner intervals/branches, occupancy and exact source-contact supports together. A proposed extension can enumerate free rail runs and actual odd/internal couplers touching the required chains; certify connectivity, disjointness and changed contacts before publication. This identifies a reusable **query capability**, not a new growth schedule, optimizer, portfolio, lane-size ladder or license to call an exact assignment solver. The state must support sparse singleton branches as well as longer runs; forcing every owner into a long two-arm template would recreate earlier Q inflation. No globally fixed unused reserve or immutable region partition is implied.

This capability is **already partly present in A**. [field._tile_orient](../../../packages/ember-qc/src/ember_qc/algorithms/factored/field.py:57) maps `p=2z+j` and `sub=2k+j` to same-course stride-2 wires; [_convert_line](../../../packages/ember-qc/src/ember_qc/algorithms/factored/field.py:700) checks physical runs and occupancy. Its class assignment plus subsequent seating is not an exact joint physical placement, and it can miss required contacts. The useful question for a retained single-state constructor is whether decisions can preserve their actual physical contact/occupancy interpretation throughout, rather than relying on an unverified geometric readout. This overlaps established geometric ideas; no novelty claim follows.

C011's additional runtime did not repair poor local coordination, so faster rail queries alone are not a mechanism result. Before any implementation, a prospective design must state what assignments it may revise and why that changes complete construction. The eventual discriminator should compare complete validity/Q and actual setup/query wall on fresh development plus hidden-witness controls, retaining order variants and all failures. Known feasible witnesses can rule out target infeasibility for those inputs; they cannot prove that a particular rail representation or move neighborhood can find them. On faulty hardware, exact adjacency must split missing rails and remove absent turns; ideal-coordinate formulas are never an authority over actual couplers.
