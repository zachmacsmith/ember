# C009 precise exploratory policy, before code

This fixes the [accepted replacement proposal](c_connected_domain_constructor_proposal.md), SHA `5763272c398b5d728ddadc3cda63b8710ac34072f931129e391ea62514eb7fc1`. That file and all C008 failures remain unchanged. No constructor call precedes this policy.

Normalize source and target labels by supplied node order; all diagnostic IDs use those ranks. One `Random(seed)` generates, in source order, a full shuffled target permutation for each source vertex. Its first min(8,|H|) sites initialize distinct singleton domains, uniformly weighted; the entire permutation fixes that owner's subsequent root, path and chain-signature ties. No graph metadata or family names are read. No RNG calls occur afterward. Empty source is valid; impossible source/target vertex or edge counts fail explicitly. Self-loops, directed graphs and multigraphs are rejected.

For owner v and connected nonempty candidate C define

`c_v(C)=|C|+lambda*(sum_{u in N(v),D in D_u} p_u(D)*1[no target edge C--D] + sum_{q in C,u!=v,D in D_u} p_u(D)*1[q in D])`.

The second term counts expected **other-owner incidences**, not a distinct-site union or already validated conflict. Contact requires a real original target coupler, including when candidates overlap. A stable softmax subtracts the minimum cost before exponentiation; `p_new=.5*p_old+.5*softmax(-c)`, then normalizes with `math.fsum`. Probabilities must be finite, nonnegative and sum to one within 1e-12. All owners use the same old probabilities in each simultaneous update. Lambda is exactly 4,8,16,32,64,128 for six epochs, eight updates each; temperature stays one.

After each epoch choose each owner's maximum-probability domain, breaking ties by Q then the sorted owner-specific physical-rank signature. Independently recount that whole assignment against original source/target adjacency. A complete timely valid map becomes the incumbent only if Q strictly improves; no soft quantity earns validity. Preserve every selected-map missing/overlap/connectivity result and first feasible Q. This is one evolving domain process, not independent constructor selection.

After the first five epochs regenerate all owners' domains from the **same frozen old domains/probabilities**. For each free-to-propose target root q, score expected neighboring-domain contact minus expected other-owner occupancy at q. Keep four roots by decreasing score then owner-specific rank. Root ranking covers the full target, without ownership blocks. From each root, grow one connected tree. Choose the first source-rank neighbor with no physical contact to any of its domains. Run one deterministic multisource Dijkstra to the union of that neighbor's physical boundaries; own-tree sites cost zero, others cost `1+expected other-owner occupancy`. Heap and adjacency ties use the proposing owner's physical rank; retain the first predecessor on equality. A reached boundary inside the current tree would already mean support. Each path must strictly reduce the number of unsupported neighboring labels, so at most degree(v) paths occur. Stop on all supported, no route or shared interruption.

Each root emits only its best completed intermediate tree, ranked by unsupported-label count, expected cost, Q and signature; no unfinished route is emitted. Combine at most four such proposals with the old domains, deduplicate exact site sets, retain the incumbent's chain if one exists, then lowest current expected cost/Q/signature to a maximum of eight. New epoch probabilities are **uniform** over the retained domains. This reset is explicit, not a continuation of discarded weights. No generated partial epoch publishes: an interruption preserves the previous domains, selected map and incumbent.

The absolute deadline is min(caller D,start+timeout), with final 0.5 seconds reserved (or the entire remaining allowance when shorter). Search stops at 19 million cumulative counted records; final cleanup/validation may use the remaining one million up to the shared 20 million limit. Counts include input/site/adjacency records, domain copies and incidence work, pair compatibility, probability operations, candidate generation and output validation. Sorting/heap/hash administration is additionally inside wall time. No work/deadline resets occur across epochs, discarded roots or output phases. A search interruption may return an earlier valid incumbent only after timely original validation. A late valid map is diagnostic only. Cleanup is one source-rank/site-rank pass of safe single-site deletions, preserving nonempty connectivity and every original contact; no fixed-point sweep. Its time ends halfway through the final reserve, preserving the remainder for full validation and output. Every completed deletion is independently checked before commitment.

**Correction and self-critique.** Pairwise support without a complete selected embedding is ambiguous: the finite domains may be globally inconsistent, or approximate coordination may fail despite a feasible selection. Only a tiny supplied-domain fixture with an explicit known feasible assignment can isolate coordination; it never initializes a constructor. Expected occupancy and missing-contact penalties are heuristic and may oscillate or favor mutually inconsistent choices. Uniform regeneration can discard useful confidence; truncation may remove the required geometry. These risks will be reported, not repaired by post-outcome cap/temperature changes. Before any public constructor, run only the three approved focused groups: connected/contact/overlap semantics, probability plus the known-feasible fixture, and interruption/late non-credit. If the central fixture fails, stop.
