# Proposed invariant-preserving path additions

**Hypothesis.** The reserved initializer provides common access, but the tested path additions destroy it. A general path-acceptance rule can retain that access after every committed addition: while original contacts remain missing, require the entire unused target F to be nonempty and connected, and require every chain incident to a missing original edge to have a neighbor in F. Then each missing pair still has a potential unused-site route. This is an availability invariant, not a promise that a route satisfying the invariant can be found.

**One path, private endpoint assignment.** Use the same eight saved initializations, original full Z12 mapping and canonical one-pass edge schedule. For each currently missing edge `(u,v)`, obtain the same deterministic shortest unused path `p[0:L]`. Do not generate an alternate path. Its proposed unused set is `F' = F minus set(p)`, independent of endpoint ownership. Compute the components of this **whole** remainder once.

Consider cuts in fixed order `L, 0, 1, ..., L-1`, removing repeated values. Cut k gives the first k path sites to u and the remainder to v. This keeps each chain connected and realizes `(u,v)`, including either empty endpoint segment. The old all-to-lower-endpoint assignment is considered first. These are assignments of one fixed path with the same added Q, not independent constructor outputs or combined witnesses.

For each cut, privately recount all realized original contacts and the resulting missing set M'. Existing contacts P must remain realized. If M' is nonempty, require F' connected and nonempty. For every source vertex incident to M', compute its resulting chain's exact boundary into F' and require a nonempty boundary. Other source chains need no future port once all their original contacts are realized. In particular, the receiving endpoints must be checked using their entire proposed chains; their new path segments can create ports, while consuming the path can remove other chains' last ports. Incidental contacts can also change which chains still need ports.

Accept the first cut passing these checks, the independent original P-plus-requested-edge gate, and a final clock check. Commit one private proposal atomically. If M' is empty, full-original-minor validity is the terminal gate; unused connectivity/ports are no longer required. If every cut fails or time expires, retain the incumbent. Save all examined cuts, rejection reasons, component/port counts, partial work and late raw proposals. No ownership of previously occupied sites changes.

**Why whole-path checks matter.** Testing each path site for articulation only in the entry unused graph is unsound: two individually removable adjacent vertices can jointly disconnect it. Recomputing articulation after each private deletion can establish unused connectivity inductively, but still says nothing about future chain ports. The direct F' component and final-chain boundary checks cover both obligations before commit; no prefix is accepted separately.

**Cheap falsifier and self-critique.** Retain 30 seconds, 1,024 still-missing visits and 256 commits per input. All component work, at most L+1 cut checks, copies, failures and validation share that deadline. Tiny gates should include adjacent non-articulation vertices whose joint removal disconnects F, a connected F' that loses another unresolved chain's last port, and a fixed path whose split ownership preserves endpoint ports. Then one run per saved initialization can test whether useful progress survives these restrictions. Count invariant-preserving commits and blocked shortest paths separately from missing contacts.

This conservative invariant may protect useless free islands, and a shortest path can fail although a longer safe route exists. Canonical scheduling and cut order may also miss a later useful assignment. Reject this fixed shortest-path policy if the guard blocks progress; do not infer that invariant-preserving routing is impossible. No alternate path search, reserve modification/refill, cleanup, constructor, MM, additional seed or cap change is proposed. Novelty remains unestablished. This document is design only; no new path call has run.

**Pre-code acceptance clarifications.** A disconnected F' does not reject the entire path before examining cuts: a cut that makes M' empty may still give a valid terminal completion. Compute each cut's actual missing set before applying its connectivity/port requirements. Also, a guard-rejected edge may become admissible after later contacts change which chains need ports. The single pass remains fixed, but unfinished exhaustion is `SCHEDULE_EXHAUSTED`, with per-edge guard reasons retained; the previous addition-only no-free-route monotonicity argument does not prove that no future invariant-preserving route exists.
