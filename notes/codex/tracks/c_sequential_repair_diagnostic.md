# Sequential supplied-state repair before a constructor integration

**Hypothesis.** Neutral transport can repair the complete state's sealed edge, but the independent query output still lacks two original contacts. A deterministic sequence of unused-path additions and neutral transport may complete an actual evolving minor while preserving every contact gained earlier. Test reach and subsequent deletion quality on all four frozen C006b final states, never by combining independent saved query outputs.

**State and scheduling.** Start with one private copy of each supplied final state. Recount P as *all currently realized original source edges*, not just the previously requested edges. In a pass, snapshot the missing original edges in canonical endpoint order. Visit that order once, skipping an edge if an earlier commit already realized it. For each still-missing edge:

1. From the current ownership, obtain its unused-component/access summary. Reuse that summary only until the next commit. If the endpoints share an unused component, compute the deterministic shortest unused-only path and assign it wholly to the lower-ID endpoint in a private proposal.
2. Otherwise, if at least one endpoint has no unused neighbor and a neutral-query slot remains, invoke the unchanged neutral query on the current incumbent. Its endpoint chains, donor scope and protected P are fixed for that call. Preserve its existing depth/beam/domain/proposal policy and inner certificate. Both-open disconnected endpoints remain outside this query eligibility; record that exclusion. Failed or ineligible attempts leave the incumbent unchanged.
3. For either proposal, run a common independent original-target gate for P plus the requested edge, then recount all represented original edges. Require P to be a subset of the new contact set and missing-edge count to decrease. Commit only after these checks and a final clock check. Save raw interrupted/rejected proposals separately; the neutral query's inner certificate does not bypass this common commit gate.

After a pass, repeat only if it committed a repair and contacts remain missing. Neutral retries are allowed only for a changed incumbent: retain `(incumbent generation, edge)` attempt keys, never a cached embedding. Thus subsequent queries can differ from the earlier independent 25-query selection; the source states and uniform scheduling rule stay fixed. Preserve every visited, skipped, ineligible, capped and unattempted edge record.

**Fixed limits.** One common 30-second deadline per supplied input covers setup, all component/BFS searches, failed queries, copies, gates, contact recounts and cleanup. Allow at most four passes, 1,024 still-missing edge visits, 256 contact-creating commits and eight neutral invocations total per input. Each invocation retains depth 4, beam 8, four donor owners, 128 donor sites measured at that invocation's entry, 64 proposals per state and 512 proposals total; the input therefore allows at most 4,096 neutral proposals. Reaching the eight-query limit prevents further ownership searches but permits unused-path visits within the other limits. No time is reset or reserved by graph identity.

**Cleanup and reporting.** Only after a timely independent gate confirms every original source edge, save the complete pre-cleanup chains/Q. Invoke the unchanged audited `deletion_closure` once with the same absolute deadline (source SHA256 `66a2bc21af6c035ca0b03f9065e2ce780ca0503b9be1af95487eb19e6be67d8b`). Preserve its completed/interrupted/alias/work fields and deletion trace. A final original-target gate distinguishes timely complete output from late diagnostic validity. Report initial/final missing edges, all P-preserving commits, added Q, Q before cleanup, removed Q and final Q, separately from constructor/MM timing. No cleanup runs on a partial minor.

**Cheap falsifier and self-critique.** Extend the neutral pocket fixture with original edges `(0,3)` and `(1,2)`: a neutral repair incidentally realizes `(0,3)`, and a subsequent unused path must finish `(1,2)` while protecting the expanded P. Test failed/late proposals without incumbent mutation and cleanup eligibility. On supplied states, the main falsifier is failure to complete the complete state through this actual sequence, or a valid completion whose cleanup remains costly and long. Canonical ordering can consume sites needed later; eight query slots may be spent before a useful later edge, and monotone P preservation excludes joint temporary contact loss. These are limitations of this fixed sequential policy. Any success remains a development-state diagnostic and requires a separately frozen full-constructor integration before performance claims.
