# B028 before-code policy: accelerate the unchanged B027 routing search

**Design only; implementation and calls await root review.** B027 remains rejected: 0/12 fresh successes, with routing taking 1146.187 of 1196.241 solver seconds. Three failures never finish initialization; twelve more finish no feasibility sweep and therefore obtain only the initial congestion-price update. Four other failures do complete one to four sweeps without becoming valid. [The completed B027 decision](b_027_transfer_results.md) supplies the evidence and all regressions.

**Hypothesis.** Compiling the existing exact joint-root search, while preserving every completed non-time decision, will make enough additional construction and congestion-update work possible within the same 60 s allowance to improve success on structurally different development inputs. The target explanation is **computational cost**. Representation, root objective, move neighborhood, acceptance and price-update schedule are held fixed. If substantially greater search exposure still fails, cost alone is inadequate; this experiment will not distinguish neighborhood from acceptance by itself.

## Exact search contract

Pack target sites in B027's already-created seeded target-rank order; pack each adjacency row in its existing target-rank order. Source and target labels stay in Python lookup maps; compiled indices represent ranks, not potentially overflowing raw labels. Source-neighbor order is unchanged. Pack actual supplied hardware edges once per constructor; no inferred Zephyr couplers or geometry substitution.

Per query, apply B027's occupancy patch exactly, including its explicit empty entries that override old ownership. The cost of site q is forbidden when quality search sees any occupant, and otherwise `1 + price(q) * occupancy(q)` in feasibility or 1 in quality. Missing prices still mean 1. Precomputation changes when cost is calculated, not its value. No price clipping, normalization or approximate distances are allowed.

Maintain dense tentative-distance, settled-distance and predecessor arrays indexed by neighbor and target rank, plus per-target settled-count and distance-sum arrays. Use distinct sentinels for unknown distance, forbidden site and no predecessor. Store enough discovery/settlement order to restore dictionaries without changing inherited consumers. Heap entries compare exactly as `(distance, source_rank(v), target_rank(q), v, q)` did: the first three fields uniquely identify the logical entry's owner/site apart from stale distance entries, so packed owner/site indices may replace the last two fields without changing order. Check this property rather than assuming integer relabeling is order preserving.

Preserve boundary insertion order and duplicate suppression, stale-entry rejection, strict `<` predecessor relaxation, full cross-neighbor settlement counts, root score `sum(distance_v(q)) - (degree - 1) * cost(q)`, and root tie by target rank. Stop only on the identical condition: after rejecting stale/settled entries, the next eligible popped distance is **strictly greater** than the best root score. Equal-score entries must still be processed. Return exactly B027's settled distances and discovered predecessor maps, not just the root. Preserve the no-neighbor root rule and the empty-boundary/no-joint-root result. Do not replace the distance-sum score with shared-tree cost, prune roots or change which routes attachment can see.

Attachment and the resulting complete proposal use the unchanged Python implementation. Only a completely finished, timely query can reach proposal publication. There is still one evolving embedding state and one constructor; no independent embedding output is selected.

```text
joint_root(neighbors, trimmed_chains, occupancy_patch, quality):
    check live deadline
    if no neighbors: execute the unchanged B027 no-neighbor rule
    lazily import the compiled module inside the charged call
    build target rank/CSR representation once if absent
    pack this query's costs, boundaries and neighbor ranks
    prove integer range is safe before conversion
    if unsafe: execute unchanged B027 joint_root with Python integers
    otherwise:
        allocate private distance/parent/settlement state and typed heap
        seed boundaries in the original order
        while exact original stopping condition has not fired:
            check deadline
            advance the same heap loop for at most 256 heap pops
            merge observed work counters; check deadline again
        unpack the exact root, settled maps, parents and receipts
        check deadline; return the complete route
```

The integer-range fallback is another implementation of the **same local query**, chosen before numerical conversion from a proved arithmetic condition. It does not execute two queries and compare them, initialize a new embedding or select among constructors. Import, typing, compilation or allocation failures are recorded failures; they must not silently trigger a different search policy.

## Arithmetic, state, deadlines and measured cost

- **Integer safety.** Use explicit signed 64-bit search arithmetic, with all range proofs evaluated using Python integers first. Let N be target size, d the number of queried neighbors and W the maximum allowed site cost. Positive-weight shortest-path labels are bounded by N·W, and a conservative bound on the summed root arithmetic is `(d + 1) * N * W`. Admit compiled arithmetic only when this and array/index/count bounds are strictly below the finite sentinel and signed maximum. Never add a sentinel. Reject negative/out-of-range packed indices before entry. Unsafe arithmetic uses the same original Python query; record its count and cost. Test values on both sides of admission and distances tied near the permitted bound. Numba uses fixed-width integers and does not enable array bounds checks by default. Keep `boundscheck=True` in this exploratory implementation and its measured headline; changing it later requires a separately documented experiment. [Numba semantics](https://numba.readthedocs.io/en/stable/reference/pysemantics.html).
- **State safety.** Arrays and heap belong to the current private query. Rank/CSR storage may persist within its one constructor, but occupancy, prices, boundaries, parents and settlement state cannot leak between queries. Pass dynamic arrays explicitly; do not capture them as compilation constants. Do not move RNG work into Numba. Preserve predecessor tie choices and dictionary contents before inherited attachment/trim; compare the resulting full chains and physical witnesses, not merely Q.
- **Deadline observation.** A 256-pop chunk is an initial cooperative polling interval, not a cap on search work. Resume the exact query until its original stopping condition or the absolute deadline. Measure maximum chunk time and deadline overshoot on the declared cases. With Z12's actual degree bound this limits each compiled return interval to a finite adjacency workload; it is not a proved wall-time bound. Preserve B027's 1 s finalization reserve for causal isolation. Abort private work after any return that reaches the deadline, and never credit late output. Compilation itself is not cooperatively interruptible; the audited outer process watchdog remains authoritative. An overlong compilation or batch is a measured cost/failure requiring a subsequent documented design change, not a reason to extend this experiment silently.
- **Counters.** Keep semantic counts for heap pushes/pops, settled labels, scanned adjacency and boundary size. Aggregate compiled counts at chunk returns and add explicit packing, allocation, conversion, compilation, fallback and polling receipts. Internal meter-call counts can change and are not speed evidence; completed roots/proposals and measured time are. Preserve B027 receipt meanings or rename changed fields explicitly. Failed and interrupted calls retain their completed observed work, stage and timing; do not invent the unfinished remainder.
- **Cold-call cost.** Lazy import, first JIT compilation, target packing, per-query packing/allocation/copies, all compiled chunks, result conversion and final validation are charged to each full constructor's solver clock. Use `cache=False`, with no eager import-time signatures or excluded warmup. Each headline call runs in a fresh audited worker process; within-call reuse is allowed. Record first compiled-call time, dispatch signatures and total calls so compilation overhead is visible. A later reuse-only kernel timing is secondary and labeled as such. Numba normally compiles a new signature on first use and can otherwise reuse disk caches, which is why this protocol disables them. [Compilation and caching](https://numba.readthedocs.io/en/stable/user/jit.html).

## One self-critique

This can make an ineffective heuristic fail faster. B027 already fails on four inputs after complete sweeps, and its root objective ignores some sharing achieved during attachment. Faster exact optimization of that objective is not an algorithmic quality contribution. Dense arrays, conversion back to dictionaries, checked indexing and repeated compilation could consume the expected gain; chunking may also alter deadline censoring even with identical non-time decisions. Thus neither matching local routes nor a warmed kernel speedup qualifies as improved embedding performance. The experiment earns a small full-constructor screen only by demonstrating substantial **charged** acceleration, then must produce original-validated success/quality evidence. B027's failures remain in the record.
