## Ordering and eligibility

The physical owner quotient is built from occupied target adjacency, including contacts between owners that are not adjacent in the source (helper lines 168–190). For a valid minor, every source edge is already represented in this quotient. Consequently this is the same neighbor relation as the original helper's union of source neighbors and physical owner neighbors (`contact_groups.py:57–64`). All target row lengths, including unused vertices, contribute to maximum target degree (lines 134–140). The source-degree bound and the priority `(-excess, -chain_length, repr_rank)` match the ordinary context for the supported integer labels (lines 192–218). Numeric ordering is deliberately used only for a group's canonical set key, while integer `repr` ordering supplies the ordinary node rank.

For sizes 2–4 the traversal remains depth, then size, then priority-ordered center. The selected tuple retains center-first neighbor-window order; sorting the canonical key does not sort this payload (lines 238–267). A group set's footprint and presence of a nonsingleton are independent of its representative. Hence rejecting ineligible occurrences before marking `seen` cannot alter the first representative of an eligible set. Removing the ordinary positive-excess filter also cannot alter that first representative: total excess is intrinsic to the set. Every eligible group from the untruncated ordinary universe therefore retains its original ordered representative. This is a statement about the complete eligible pools; the new footprint ordering and final cap intentionally select a different prefix.

Singletons are exactly chains of length 2–64. Larger groups have size 2–4, at least one nonsingleton, and total **entry** footprint at most 64 (lines 220–267). There is no positive-excess test. A singleton center with a nonsingleton partner is allowed. The full entry footprint includes a site that might later be deleted. Connectivity, articulation, seed selection and actual contraction are not inferred by these filters. Under the valid-entry premise, each center-window union is connected because each neighbor chain contacts the center chain.

All eligible pools are completed and sorted by `(footprint, canonical_key)` before interleaving sizes 1, 2, 3 and 4 (lines 276–307). Exhausted streams are skipped. The cap applies only to the resulting interleave; even limit zero completes pool generation and sorting before returning an empty vector. Pairs cover every quotient edge once, but triples and quadruples cover contiguous neighbor windows only. They do not enumerate all connected subsets.

## Cost and incomplete preparation

Let `n` be the number of owners, `Q` the occupied sites, and `E` the number of undirected quotient edges. The complete eligible pool size is at most `n + 5E`: at most `n` singletons, `E` pairs, and `2E` raw windows of each larger size. The shrinking active-center list avoids scanning all owners at each depth; its complete window-center visit count is `6E`. With `E <= QΔ/2` and source edges contained in the quotient, the stated work bound `O(|V_target| + QΔ + (n+E) log(n+E))` and storage bound `O(Q+n+E)` are consistent with the implementation. Integer label comparison/encoding costs are not unit cost for unbounded label bit length; the diagnostic uses bounded canonical integer labels.

Sorting, vector materialization, JSON encoding and hashing occur before publication and remain within cooperative wall accounting. Deadline checks surround builtin sorts and encoding/hash operations. A deadline crossed at a checked stage, including finalization, returns `None`, never a discovered group prefix (lines 309–341). Partial pool counts and generation/materialization flags remain evidence of unfinished work. Invalid input likewise returns no group vector. An empty completed universe returns `[]`, which the worker must distinguish from `None`.

Typed event counts measure the named records and operations; they are neither CPU instructions nor exchange search work. As with any cooperative return check, a small amount of metadata bookkeeping follows the last timestamp. The encompassing worker must measure the actual call and reject late arm completion. Each arm must pay its own complete group-generation cost inside the same absolute arm deadline; no deadline reset or free precomputed group vector is implied by this review.

The helper requires stable simple undirected graphs and an independently valid entry. Its validation is intentionally limited to scalar/container/coverage/occupancy structure and examined adjacency rows (lines 3–6, 87–109). It does not certify source symmetry, unused target edges, chain connectivity or logical edge coverage. Unexpected Python exceptions propagate and require the worker's failure record; they do not return a usable prefix. Caller validation and process supervision are separate review obligations.
